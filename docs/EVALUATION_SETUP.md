# Evaluation Setup — AgentOS v1 Freeze

## Hardware

The primary development/evaluation machine is:

- CPU: Intel Core i7-12700F, 12th generation
- RAM: 16 GB
- GPU: NVIDIA Quadro K620, 2 GB
- OS target: Ubuntu/Debian-based Linux for the eventual bootable environment
- Development prototype: Windows-compatible Python runtime for the current capstone phase

The local prototype intentionally uses CPU inference because the available 2 GB GPU memory is not a practical target for the selected local models.

## Software

- Python: 3.14.x in the current validation environment
- FastAPI + Uvicorn
- Pydantic
- Requests
- psutil
- pytest
- Ollama for local model inference

## Models

- Primary model: Qwen2.5 1.5B
- Small model tier: Qwen2.5 0.5B
- Offline evaluation backend: MockLLM using the same `LLMClient` interface

## Scheduler configurations

The runtime supports:

- FIFO
- Round-Robin
- Priority
- Resource-Aware

The scheduler is selected with `AGENTOS_SCHEDULER`.

## Policy configurations

Policy enforcement is enabled by default:

`AGENTOS_POLICY_ENFORCEMENT=on`

The Day 6 ablation can set it to `off` without changing agent/runtime code.

## Concurrency

The supported runtime concurrency limits are 1 and 2. The v1 baseline uses:

`AGENTOS_MAX_CONCURRENCY=1`

## Workload

The Day 5 MockLLM workload contains five deterministic general tasks covering scheduler behavior, policy, monitoring, memory, and the end-to-end request flow. The workload is generated by `scripts/day5_mock_workload.py` and written to `experiments/day5_mock_workload.csv`.

## Seeds and reproducibility

The current v1 workload is deterministic and does not use stochastic sampling or random seeds. Task IDs and prompts are fixed by the workload script. Model-backed experiments should record model name, backend, scheduler, concurrency, model tier, and runtime metrics for each run.

## Metrics

The agreed result schema is defined by `backend/results_csv.py` and includes timestamp, task/agent information, status, workload attributes, token count, LLM latency, end-to-end latency, and backend.

Policy events are written to `experiments/metrics.csv`, including allowed/blocked tool calls and runtime failure events.
